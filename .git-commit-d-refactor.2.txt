refactor(subscription): drop user-CRUD from internal/subscription (d-refactor.2)

The v0.4.0-d consolidation's first sub-step: the user-CRUD surface
(Store + Service + admin handler) has moved out of internal/subscription
and into internal/users. The subscription package is now a pure
render orchestrator (plus a plan / pool / member Store).

This is the single-PR cut of the 5-PR plan in the v0.4.0-d audit.
The d.1 + d-refactor.1 wire-format alignment (User / UserStatus as
type aliases for users.User / users.Status) means the render code
(15 files) does not need a single edit. The admin handler is the
only meaningful signature change (it calls s.users directly for
Get/Update; the thin Service wrappers cover Create/List/Rotate
until d-refactor.3 moves the handler out).

Behaviour changes worth flagging:

  * sub_token is now 32 bytes / 64 hex chars (d.1 design; the d.0
    16-byte / 32-hex default is gone).
  * RotateSubToken grace=0 no longer invalidates the prev token
    immediately — the d.1 users.Service maps grace <= 0 to the
    canonical 24h default. The pre-existing test that asserted
    the d.0 behaviour is rewritten as a documentation test.

Follow-ups:

  * d-refactor.3: move admin_handler.go to internal/users;
    replace subscription.AdminRouter mount with users.Router;
    drop the four thin wrappers from subscription.Service.
  * d-refactor.4: cleanup pass (drop the CreateUserInput alias,
    the DefaultSubTokenRotationGrace re-export, trim docs).

Net: -748 lines (subscription loses ~700, users gains ~50).
