test(e2e): add Playwright setup + v0.8.28 dropdowns regression guard

Sets up the Playwright E2E test infrastructure
for the admin UI and adds the first spec file:
the v0.8.28 dropdowns-regression test.

### What's in this PR

- `frontend/playwright.config.ts` - Playwright
  config. Uses BASE_URL from env (default
  http://localhost:5173 = local vite dev
  server), single chromium project, serial
  execution (1 worker), 0 retries, screenshot
  + trace on failure.
- `frontend/e2e/helpers/auth.ts` - admin login
  helper. Caches the storageState in a
  module-level promise so the login runs ONCE
  per test worker (not once per test). The
  helper throws on empty E2E_ADMIN_PASSWORD
  (refuses to silently use a default that may
  not match the real admin).
- `frontend/e2e/01-auth.spec.ts` - 3 tests:
  1. `lands on the dashboard after login` -
     smoke test that the auth flow works
     end-to-end
  2. `dropdowns are visible (regression for the
     v0.8.28 "all dropdowns are invisible" bug)`
     - the actual regression guard. Navigates
     to Inbounds, opens the Create dialog,
     clicks the protocol <Select> trigger,
     asserts the listbox (popup) is visible
     (Playwright's toBeVisible checks computed
     style, not just DOM presence) and has a
     non-zero bounding box, asserts a <option>
     is visible
  3. `clears the session and redirects to
     /login on logout` - smoke test for the
     logout flow
- `frontend/package.json` - adds @playwright/test
  ^1.49.1 devDep + 5 new npm scripts:
  - `e2e` - run the suite (uses BASE_URL env
    or default http://localhost:5173)
  - `e2e:headed` - headed mode for debugging
  - `e2e:debug` - debug mode (pauses on failure)
  - `e2e:prod` - run against the prod panel
    (E2E_BASE_URL must be set; E2E_NO_WEBSERVER=1
    is implied)
  - `e2e:install` - install chromium + deps
- `.github/workflows/e2e.yml` - CI workflow
  that runs the suite. Triggered by
  workflow_dispatch (manual) and on a daily
  cron (03:00 UTC) to catch prod-side
  regressions. Supports both the prod path
  (default) and the dev docker-compose stack
  (via the `compose` input).
  Requires the GitHub Actions secret
  `E2E_ADMIN_PASSWORD` (the prod admin
  password from 1Password) + `PANEL_BASE_URL`
  (the prod panel base URL).

### Why this PR is just the setup + 1 spec

The full test suite (12+ views, ~40+ scenarios
in total) is too big for one PR. The plan is
to ship the setup first so the user can verify
the infrastructure works on the live prod panel
(navigate to Inbounds, click Create, assert
the protocol dropdown is visible) before
committing to the full test matrix in
follow-up PRs:

  - PR-A (this): setup + auth + dashboard +
    dropdowns regression guard
  - PR-B: read-only views (Profile, Settings,
    Audits, Backups, Subscription)
  - PR-C: form-heavy views with selects
    (Inbounds, Hosts)
  - PR-D: Nodes (the 4 dialogs - most complex)
  - PR-E: Users, Plans, Webhooks

The dropdowns-regression test in this PR is
the highest-value test of the whole suite -
it directly guards against the v0.8.28 bug
that started this whole thread.

### Run it locally (against the prod panel)

```
cd frontend
pnpm install
pnpm exec playwright install --with-deps chromium
E2E_BASE_URL=https://<prod-host>/<sub-path>/ \
E2E_ADMIN_PASSWORD=<password> \
  pnpm e2e:prod
```

### Run it locally (against the dev stack)

```
cd deploy/docker && cp .env.example .env
docker compose -f docker-compose.dev.yml up -d
cd ../../backend && make run  # in another terminal
cd ../frontend && pnpm dev   # in another terminal
cd frontend && pnpm e2e
```

### Out of scope (deferred)

- A per-view test for every admin view (12+
  spec files, ~40+ tests). Will land in PRs
  B-E as outlined above.
- WebKit / Firefox projects. The admin UI is
  Chromium-only by design.
- Visual regression snapshots. Out of scope;
  can be added later via Playwright's
  `toHaveScreenshot()` matcher.
